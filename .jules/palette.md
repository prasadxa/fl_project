## 2025-03-22 - Toggle Button Accessibility
**Learning:** For custom tab or toggle button groups (like Scan Type or Report Format selectors), visual classes like `bg-teal-600 text-white` are not enough for screen readers. Using `role="group"` on the container with a proper label (`aria-labelledby` or `aria-label`), and setting `aria-pressed={isActive}` on the buttons is critical for conveying the current selection state to assistive technologies. Keyboard focus styles (like `focus-visible:ring-2`) should also be applied to these buttons since they are interactive elements.
**Action:** Always verify that custom UI controls that act as radio buttons or tabs have appropriate ARIA roles (`group`, `radiogroup`, or `tablist`) and state attributes (`aria-pressed`, `aria-checked`, or `aria-selected`), along with clear visual focus indicators.

## 2025-03-24 - Skip-to-Content Link implementation
**Learning:** Skip-to-content links should be accessible and visually apparent only upon keyboard focus. Using a standard \`sr-only focus:not-sr-only\` technique can sometimes cause jarring layout shifts when the element suddenly enters the document flow. An off-screen translation approach (\`absolute -top-[100px] focus:top-[10px]\`) ensures the element appears smoothly without affecting layout. It is also important that the target container (e.g. \`<main>\`) receives an \`id\`, \`tabIndex="-1"\`, and \`focus:outline-none\` so that programmatic focus shifts securely without triggering a visible outline on the container.
**Action:** Always implement skip-to-content links with off-screen positioning techniques instead of \`sr-only\` to avoid layout shifts, and always configure the target container to gracefully handle programmatic focus.
