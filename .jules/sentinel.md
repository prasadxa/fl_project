## 2024-05-24 - LaTeX Injection in PDF Generator
**Vulnerability:** Arbitrary user input (e.g., patient name, patient ID) was embedded directly into a LaTeX document template in `backend/latex_report.py` without any sanitization.
**Learning:** Using Python's `f-strings` to directly insert untrusted data into a `.tex` file creates a critical LaTeX injection vulnerability. Malicious input containing backslashes could execute arbitrary LaTeX commands, potentially allowing file reads or even RCE depending on the compiler's configuration (e.g., `\input{/etc/passwd}`). Additionally, sequential `.replace()` string operations to escape LaTeX are bug-prone; they often lead to "double escaping" if a backslash is replaced first, then a subsequent `{` or `}` is replaced with another backslash. Finally, attempting to escape input using `re.sub` requires coercing non-string types (e.g., datetimes or integers) to strings beforehand to prevent runtime `TypeError`s.
**Prevention:** Implement a robust `escape_latex` function using a single-pass regex replacement that maps special LaTeX characters to their safe equivalents. Ensure all arguments passed to `escape_latex` are cast to a string (e.g., `text = str(text)`) before performing the regex substitution to avoid TypeErrors. Apply this function universally to any user-controllable input before string interpolation in the `.tex` file.
