## 2025-03-22 - Toggle Button Accessibility
**Learning:** For custom tab or toggle button groups (like Scan Type or Report Format selectors), visual classes like `bg-teal-600 text-white` are not enough for screen readers. Using `role="group"` on the container with a proper label (`aria-labelledby` or `aria-label`), and setting `aria-pressed={isActive}` on the buttons is critical for conveying the current selection state to assistive technologies. Keyboard focus styles (like `focus-visible:ring-2`) should also be applied to these buttons since they are interactive elements.
**Action:** Always verify that custom UI controls that act as radio buttons or tabs have appropriate ARIA roles (`group`, `radiogroup`, or `tablist`) and state attributes (`aria-pressed`, `aria-checked`, or `aria-selected`), along with clear visual focus indicators.

## 2025-03-24 - Skip to Main Content Link Accessibility
**Learning:** For users relying on keyboard navigation or screen readers, navigating past a large global header (like the sticky top navbar) on every page load can be tedious. A "Skip to main content" link at the very top of the DOM provides an essential shortcut. When using Tailwind CSS, `sr-only focus:not-sr-only focus:absolute` works well for the skip link, ensuring it stays hidden until focused. The target container (like `<main>`) must have `tabIndex={-1}` to accept programmatic focus from the link, and `outline-none` should be applied so that clicking the link or navigating to the main content doesn't create an unwanted focus ring around the entire page body.
**Action:** Always include a "Skip to main content" link for pages with global navigation headers, and ensure the target `<main>` container has `tabIndex={-1}` and `outline-none` to gracefully handle the programmatic focus shift.
